# AI 错误与修正记录

以下为本次开发真实发生的问题。AI 指编写实现代码的 Codex；边界输入由程序构造，不冒称 Qwen 在正式评测中实际输出过这些异常字段。历史修复日志保留在原作业工程，新仓库保留对应测试，没有用事后编造的“模型幻觉”凑数。

| 项目 | AI 最初给出的实现 | 错在哪里 | 如何发现 | 最终修正 |
|---|---|---|---|---|
| 1. 资料提取截断 | 在遇到第一个 `\\clearpage` 时停止读取报告正文 | 分页是排版命令，并不代表全文结束；初次只提取到 1076 个汉字，达不到 1500 字要求 | 实际运行 `prepare_materials.py`，查看其字数输出；修正后提取到 3993 个汉字 | 以参考文献开始位置作为正文结束，移除分页命令但继续读取后文；按内容分成 MD 与 TXT |
| 2. 过度相信模型 JSON 字段 | 直接遍历 `missing`，直接用 `citations[].id` 查字典 | JSON 语法正确不等于字段类型正确；`missing:7` 导致 TypeError，`id:[]` 导致 unhashable type | 边界测试实际得到两条错误堆栈，对应 `test_regressions.py` 中的字段类型检查 | 在使用前校验布尔值、列表、字符串与引用 ID 类型；异常模型回答进入 rejected，不冒充正确拒答 |
| 3. 混合 PDF 漏页 | 只有整个 PDF 都无文字时才报错 | 一页可提取、一页为扫描图时，会静默丢掉扫描页，影响知识库完整性 | 构造两页 PDF，要求扫描页提示 OCR；初次测试明确失败 | 逐页检测“没有文字但有图片”，明确提示页码及 OCR 要求；不把局部导入成功说成全文成功 |

修正后三类问题对应的检查连同中文检索、假引用拦截和三格式解析，共 6 项测试通过。它们证明这些边界处理已改善，不代表所有幻觉已消除。

收获：让 AI 写代码可以减少重复劳动，但要把“它说能做”变成可观察的输入、输出和失败条件。字数、异常堆栈、实际 PDF 解析结果，比“代码看起来合理”更可靠。


第二轮补充：Figure统计校验曾用英文单词边界匹配图号。图号紧邻中文时，数字和中文都属于正则单词字符，导致漏识别。新增“Figure 4中”的边界测试实跑失败，改为ASCII编号边界后只复跑该项通过。中间v4完整运行还暴露长文件名抄写误拦截与不同数据集共用真数值的问题，v4.1改为短编号精确映射并检查指定结果对象；四项新行为测试全部通过。上述为代码问题记录，不能替代对模型40条回答的人工评分。

短编号提示的后续错误：在通用有答案JSON示例中填入表格facts，会诱导模型给普通正文也生成r1:c1。真实Q01至Q06出现多次拦截，已停止该不完整运行并保留日志。修正为默认facts为空，逐条证据标明text/table，表格只允许选择实际allowed_cells；未通过忽略虚构单元格来放行。

最后的表格诊断中，模型选出了真实r5:c3但漏写id。程序只在已引用的表格中该单元格来源唯一时恢复ID，并显式记录source_resolved_from_unique_cited_table；多表歧义、未知ID或不存在单元格继续拒绝。该新行为单项测试通过，没有重跑旧项。完整复测沿用同一常驻模型，避免再次冷加载。

完整v4.2显示混合正文与表格的facts协议仍反复失败，增加提示约束不足以消除。最终v4.3简化为模型仅回答并选出处，保留完整表格与程序计算；旧facts只作兼容校验，不再要求生成。另修正数值校验将“略低0.1”误认为不支持的问题：差值幅度可由真实负差值支持，但全称“都领先”与任一负差值冲突会拦截。新增该行为单项测试通过，旧检查未复跑。

聊天入口改造：原界面将所有输入送入文档问答，普通自我介绍也会触发证据不足或 JSON 校验失败。现将普通多轮聊天与文档问答分开，保留显式资料选择与独立评测范围。真实聊天测试又发现导出配置的 eos_token_id 为 248044，而分词器的对话结束符为 248046，导致回答后继续模拟下一轮用户。聊天生成显式使用分词器结束符并兼容原结束符，论文评测的生成参数保持原样。

首页元信息漏检：真实作者与标题查询均未检索到 c001，标题查询甚至触发 BM25 无匹配词。PDF 与片段中实际保留了姓名、单位和标题，问题出在通用问法与原文词汇不重合，向量检索也选中了无关正文。v4.4 对作者、标题和机构问题补取真实首页片段，修正存在补充证据却因 Top-3 为空而提前拒答的分支。四项定向测试覆盖长署名区、双语问法、真实导入片段、空命中时的生成与引用链路。原20题、40条回答与评分保持不变，未中断用户正在运行的 CLI，当前进程需重启后生效。
